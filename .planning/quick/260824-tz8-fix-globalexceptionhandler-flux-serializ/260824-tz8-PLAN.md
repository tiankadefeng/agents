<objective>
Fix GlobalExceptionHandler: its `@ExceptionHandler` method returns a bare `Flux<ServerSentEvent<String>>`, which Spring MVC cannot serialize on the exception-handler path. Replace with direct SSE wire-format writing through `HttpServletResponse`, preserving the D-08 contract (HTTP 200 + text/event-stream + single ErrorEvent frame, message = exception type + message, no stacktrace). Add server-side logging of the original exception and a regression test.

Purpose: Any pre-stream exception (e.g., malformed JSON body) on SSE endpoints currently produces `HttpMessageNotWritableException: No converter for [FluxJust]` followed by a Tomcat `RecycleRequiredException`, and the client never receives the D-08 ErrorEvent frame - the frontend throws `HTTP 400/500` instead of showing the error message. This error path has never been test-covered, which is why it went unnoticed.

Output: A fixed `GlobalExceptionHandler.java` (void handler, manual SSE write, WARN logging) and a new `GlobalExceptionHandlerTest.java` regression test proving the D-08 contract on the error path.

Root cause (verified, do not re-investigate): Normal controller methods returning `Flux<ServerSentEvent>` are handled by `ResponseBodyEmitterReturnValueHandler`/`ReactiveTypeHandler` (async SSE). But `@ExceptionHandler` method return values are processed by `ExceptionHandlerExceptionResolver`, whose return-value handler list has NO reactive/emitter support - a `Flux` return falls through to `RequestResponseBodyMethodProcessor` (@RestControllerAdvice = @ResponseBody semantics), which tries to serialize the `FluxJust` object itself via HttpMessageConverter. The original mapping's `produces=text/event-stream` pins the negotiated Content-Type, no converter can write `FluxJust`, so it throws `HttpMessageNotWritableException`. (The current class javadoc claims the bare-Flux-plus-HttpServletResponse approach works - that rationale is wrong and must be rewritten.) The fix: return `void`, write the SSE frame directly to the response. This is safe because a handler method declaring an `HttpServletResponse` parameter marks the response as fully handled (`mavContainer.setRequestHandled(true)`), so Spring performs no further return-value processing.
</objective>
