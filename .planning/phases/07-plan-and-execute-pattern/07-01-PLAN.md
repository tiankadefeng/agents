  <name>Task 2: Create PlanAndExecuteAgentPattern</name>
  <files>
    src/main/java/com/agents/agent/patterns/PlanAndExecuteAgentPattern.java
  </files>
  <action>
    Create `@Component` implementing `AgentPattern` with `id()="planExecute"`, `displayName()="Plan-and-Execute 计划与执行"`, `description()="先规划再逐步执行，步骤失败可重新规划"`.

    **Injections:**
    - `ChatClient.Builder chatClientBuilder` — for Planner (single call + JSON parsing), Executor sub-agents (with tools), Summary step, LLM self-evaluation, and Replan
    - `ObjectMapper objectMapper` — for JSON parsing of Planner output
    - `ToolRegistry toolRegistry` — for sub-agent tool access (per D-04)

    **Constants (declare as private static final):**
    - `MAX_REPLAN = 3` — safety limit for replan loop
    - `PLANNER_SYSTEM_PROMPT` — instructs LLM to output structured JSON plan with steps array, each element containing description and expectedOutput. Schema: `{ "steps": [{ "stepNumber": int, "description": string, "expectedOutput": string }] }`. Output ONLY JSON, no markdown wrapping.
    - `STEP_SYSTEM_PROMPT` — instructs sub-agent LLM to execute a single step. Contains: available tools (weather/calculator/time), instruction to call tools if needed, instruction to output the step result. Each step is independent — does not know about other steps.
    - `SUMMARY_SYSTEM_PROMPT` — instructs LLM to synthesize all step results into a final answer. Given the original question and all step results (stepNumber, description, result), produce a comprehensive final answer.
    - `SELF_EVAL_SYSTEM_PROMPT` — instructs LLM to evaluate whether a step's result meets the expected output. Returns "yes" or "no" with brief explanation.
    - `REPLAN_SYSTEM_PROMPT` — instructs LLM to generate a new plan for remaining steps. Given: original question, completed steps (with results), failed step (with error), generate a new plan for the remaining steps (from failed step onward).

    **execute(AgentContext ctx) implementation using Flux.create sink:**

    ```
    1. Call Planner: chatClientBuilder.defaultSystem(PLANNER_PROMPT).build()
       .prompt().user(ctx.question()).call().content()
       → Parse JSON using extractJson() + objectMapper.readTree()
       → Build List<Step> from JSON array
       → Emit sink.next(new PlanEvent(Instant.now(), steps))
       → If JSON parsing fails → emit ErrorEvent + complete

    2. Executor loop:
       currentStepIndex = 0
       completedResults = new ArrayList<StepResult>()  // record or pair
       replanCount = 0

       while (currentStepIndex < steps.size() && replanCount < MAX_REPLAN):
         step = steps.get(currentStepIndex)
         emit sink.next(new StepStartEvent(now, step.stepNumber(), step.description()))

         // Sub-agent execution (per D-03, D-04):
         toolCallbacks = toolRegistry.forPattern("planExecute")
         stepClient = chatClientBuilder.defaultSystem(STEP_SYSTEM_PROMPT).build()
         result = stepClient.prompt()
           .user(u -> u.text("问题: {0}\n步骤描述: {1}\n预期输出: {2}",
               ctx.question(), step.description(), step.expectedOutput()))
           .tools(toolCallbacks)
           .call()
           .content()
         if (result == null) result = ""

         // Failure detection (per D-07):
         failed = false
         // Step 1: Exception check — if result is blank or tool call threw, mark failed
         if (result.isBlank()) {
           failed = true
         } else {
           // Step 2: LLM self-evaluation
           evalClient = chatClientBuilder.defaultSystem(SELF_EVAL_SYSTEM_PROMPT).build()
           evalResponse = evalClient.prompt()
             .user(u -> u.text("步骤: {0}\n预期输出: {1}\n实际结果: {2}",
                 step.description(), step.expectedOutput(), result))
             .call()
             .content()
           // Parse evalResponse: if contains "no" (case-insensitive), mark failed
           failed = (evalResponse != null && evalResponse.toLowerCase().contains("no")
               && !evalResponse.toLowerCase().contains("yes"))
         }

         if (failed):
           emit sink.next(new StepCompleteEvent(now, step.stepNumber(), "failed", result))
           // Replan (per D-06):
           replanClient = chatClientBuilder.defaultSystem(REPLAN_SYSTEM_PROMPT).build()
           replanResponse = replanClient.prompt()
             .user(u -> u.text("原始问题: {0}\n已完成步骤: {1}\n失败步骤: {2} (步骤号 {3}, 错误: {4})",
                 ctx.question(),
                 formatResults(completedResults),
                 step.description(), step.stepNumber(), result))
             .call()
             .content()
           // Parse new plan JSON → new List<Step>
           newSteps = parsePlanJson(replanResponse)
           if (newSteps != null && !newSteps.isEmpty()):
             steps = newSteps
             emit sink.next(new PlanEvent(Instant.now(), steps))
           replanCount++
           // Don't increment currentStepIndex — re-execute from current step with new plan
         else:
           emit sink.next(new StepCompleteEvent(now, step.stepNumber(), "done", result))
           completedResults.add(new StepResult(step, result))
           currentStepIndex++

       // Check if all steps failed (replan exhausted)
       if (replanCount >= MAX_REPLAN && currentStepIndex < steps.size()):
         emit sink.next(new ErrorEvent(Instant.now(),
             "重新规划次数已达上限，请简化问题后重试。"))
         sink.complete()
         return

    3. Summary step (per D-05):
       summaryClient = chatClientBuilder.defaultSystem(SUMMARY_SYSTEM_PROMPT).build()
       summaryResult = summaryClient.prompt()
         .user(u -> u.text("原始问题: {0}\n\n各步骤执行结果:\n{1}",
             ctx.question(), formatResults(completedResults)))
         .call()
         .content()
       if (summaryResult != null && !summaryResult.isBlank()):
         emit sink.next(new FinalAnswerEvent(Instant.now(), summaryResult))
       else:
         emit sink.next(new ErrorEvent(Instant.now(), "所有步骤均执行失败，无法生成最终答案。请简化问题后重试。"))

       sink.complete()
    ```

    **Helper methods:**
    - `extractJson(String raw)` — same as SelfAskAgentPattern.extractJson(): strip ```json/``` markers, extract first { to last }
    - `parsePlanJson(String json)` — parse JSON into List<Step>, return null on failure
    - `formatResults(List<StepResult> results)` — format completed steps as string for prompts
    - `StepResult` — private inner record or class to hold (Step step, String result)

    **Error handling:**
    - Wrap all LLM calls in try-catch; on exception, emit ErrorEvent with Chinese message + complete
    - If Planner returns blank or invalid JSON, emit ErrorEvent + complete
    - If all replans exhausted, emit ErrorEvent + complete
    - If summary step fails, emit ErrorEvent + complete

    **Important implementation notes:**
    - Use `tools.jackson.databind.ObjectMapper` and `tools.jackson.databind.JsonNode` (matching Self-Ask import convention)
    - Use `Flux.create` sink pattern (matching ReAct and Self-Ask)
    - Do NOT use `Sinks.Many` — `Flux.create` with `FluxSink` is sufficient for the sequential pattern
    - The step executor uses `ChatClient.Builder` with `.tools(toolCallbacks)` — Spring AI's tool calling advisor handles tool execution automatically within each sub-agent call. This is intentional: sub-agent tool calls are internal to the sub-agent, not exposed as separate events.
    - MAX_REPLAN = 3 prevents infinite replan loops
    - LLM self-evaluation: parse response for "yes"/"no" keywords. If "no" appears (case-insensitive) and "yes" does not also appear, mark as failed. This is a simple heuristic — the self-evaluation prompt instructs the LLM to start with "yes" or "no".
