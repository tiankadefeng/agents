Spring AI 2.0 API signatures (VERIFIED via jar 反编译 in 04-RESEARCH.md):
- `org.springframework.ai.tool.ToolCallback` interface: `getToolDefinition()`, `call(String)` returns String
- `org.springframework.ai.tool.definition.ToolDefinition` interface: `name()`, `description()`, `inputSchema()` (returns String JSON schema)
- `ToolCallback.call(String toolInput)` accepts flat JSON args (e.g. `{"city":"北京"}`), returns String result. May throw ToolExecutionException (RuntimeException).

Jackson 3.x (Spring Boot 4.1): ObjectMapper import is `tools.jackson.databind.ObjectMapper` (NOT `com.fasterxml.jackson.databind.ObjectMapper`). Confirmed by existing SseEventEmitter.java which imports `tools.jackson.databind.ObjectMapper`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → API | Untrusted toolName (path variable), arguments Map (request body JSON) cross into ToolController. toolName goes through byName Map lookup; arguments get serialized and passed to ToolCallback.call(). |
| API → tool layer | ToolController calls ToolCallback.call(jsonArgs) - the tool's own validation (exp4j, WeatherTool switch) handles untrusted args. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-04 | Information Disclosure | POST /api/tools/{toolName}/invoke → byName lookup | mitigate | Unknown toolName caught by `catch (NoSuchToolException)` returns HTTP 404 + `{"error":"未知工具：{toolName}"}`. Does NOT leak registered tool list (only GET /api/tools intentionally exposes it). ToolControllerTest#shouldReturn404ForUnknownTool verifies. |
| T-4-05 | Information Disclosure | ToolController catch (Exception ex) | mitigate | Returns `{"error":"工具执行失败：" + ex.getMessage()}` - message only, NO stacktrace (ASVS L1 V7.1 compliance, follows GlobalExceptionHandler T-2-13 pattern). ToolControllerTest#shouldInvokeCalculatorTool verifies happy path; error path returns 500 with message only. |
| T-4-06 | Tampering | @RequestBody ToolInvokeRequest JSON parse | accept | Malformed JSON body → Jackson parse exception handled by Spring MVC automatically returning 400 Bad Request. ToolController does not need manual JSON parse handling (Spring MVC invariant). |
| T-4-03 | Tampering | POST /api/tools/calculator/invoke with malicious expression | mitigate | Delegated to CalculatorTool (04-01) which uses exp4j (Shunting Yard, no eval, no code injection) and catches IllegalArgument/ArithmeticException returning error JSON. ToolController just relays the tool's JSON result. |
| T-4-09 | Spoofing | POST toolName path injection | accept | toolName is a path variable looked up in a Map - no file path, no system call. No traversal risk (RESEARCH.md §Security Domain verified). |

## Notes
- ToolController is a plain REST controller (application/json), NOT SSE (unlike AgentController). No SSRF - no external requests made.
- Open endpoint, no auth (PROJECT.md Out of Scope - local teaching tool). Accepted per ASVS V2/V3/V4 not applicable.
- Tool results may contain untrusted content (e.g. WeatherTool mock city name echo). Phase 5 ReAct handles prompt-injection via system prompt guidance - out of Phase 4 scope.
</threat_model>
