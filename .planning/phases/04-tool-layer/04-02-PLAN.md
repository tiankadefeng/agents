<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tool name input | Untrusted String toolName crosses from ToolController (Plan 03) into ToolRegistry.byName(). Map lookup must handle arbitrary names safely. |
| Tool bean collection | Spring DI collects @Tool beans into List<Object> toolBeans at startup. Registry builds immutable Map. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-04 | Information Disclosure | ToolRegistry.byName(toolName) → NoSuchToolException | mitigate | Unknown tool name returns 404 via NoSuchToolException caught by ToolController. Does NOT leak the registered tool list (only GET /api/tools intentionally exposes it). ToolControllerTest#shouldReturn404ForUnknownTool verifies. |
| T-4-Map | Tampering | ToolRegistry.byName Map construction | mitigate | `Collectors.toUnmodifiableMap` returns immutable Map (follows AgentRegistry T-2-15 pattern). Registry built at startup, read-only at runtime - cannot be tampered. |
| T-4-08 | Spoofing | ToolRegistry constructor providers injection | accept | `@Autowired(required = false) List<ToolCallbackProvider> providers` is empty in Phase 4 (no MCP starter). Phase 11 adds SyncMcpToolCallbackProvider (trusted framework bean). No untrusted input in Phase 4. |
| T-4-SC | Tampering | MCP providers (deferred to Phase 11) | accept | No MCP provider present in Phase 4. When added in Phase 11, MCP server tool definitions are treated as untrusted (Phase 5 ReAct system prompt guidance). Out of Phase 4 scope. |

## Notes
- NoSuchToolException message `未知工具：{toolName}` is safe (echoes input, no internal state). Accepted for teaching tool.
- ToolRegistry has no persistence, no I/O, no sensitive data - no data-protection threats.
- T-4-03 (expression injection) is mitigated in 04-01 CalculatorTool. T-4-05 (stacktrace leak) and T-4-06 (JSON parse) are handled in Plan 03 (ToolController).
