<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tool method input | Untrusted String input (city name, math expression) crosses from LLM or HTTP caller into tool method. exp4j evaluator and WeatherTool switch must handle arbitrary input safely. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-03 | Tampering | CalculatorTool.calculate(String expression) | mitigate | exp4j uses Dijkstra Shunting Yard algorithm - pure math, no variable assignment, no string operations, no I/O, no reflection. Safely rejects non-math input via IllegalArgumentException caught and returned as error JSON. No ScriptEngine eval (which would allow code injection). |
| T-4-SC | Tampering | Maven dependency `net.objecthunter:exp4j:0.4.8` | mitigate | slopcheck flagged [SUS] due to its own URL-encoding bug. Manual verification completed in 04-RESEARCH.md §Package Legitimacy Audit: Maven Central metadata confirms (`numFound:1`, `latestVersion:0.4.8`, `timestamp:1485784783000`), POM declares Apache License 2.0, GitHub repo `fasseg/exp4j` returns HTTP 200, 9+ years stable with 13 versions. No blocking checkpoint required - audit trail preserved in RESEARCH.md. |
| T-4-03b | Information Disclosure | CalculatorTool error JSON | accept | Error JSON includes `ex.getMessage()` from exp4j. exp4j messages are math-specific (e.g., "Unknown operator '...'"), no sensitive internal state. Acceptable for teaching tool. |
| T-4-07 | Denial of Service | CalculatorTool with pathological expression | accept | exp4j has no memory allocation limits, but teaching context means inputs are short. No mitigation needed for Phase 4. Phase 5 ReAct may add input length validation if needed. |

## Notes
- WeatherTool and TimeTool have no input validation threats (WeatherTool uses switch with default fallback; TimeTool takes no input).
- All 3 tool classes are pure (no side effects, no I/O, no state) - no persistence or state-related threats.
- T-4-04 (unknown tool enumeration) and T-4-05 (stacktrace leak) are mitigated in Plan 03 (ToolController), not this plan.
- T-4-06 (JSON parse exception) is handled by Spring MVC automatically, not in tool classes.
